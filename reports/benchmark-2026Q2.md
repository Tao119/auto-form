## ワークフロー構成

```
L-01: パラメータ設定
  ↓
L-02a: サブエリアクエリ生成（都道府県 → 市区町村 × キーワード）
  ↓
L-02b: Google Places API Text Search（最大20件/クエリ）
  ↓
L-02c: 重複除去・集約
  ↓
L-03: 並列HP＋フォーム抽出（scrape-forms-bulk, Playwright）
  ↓
L-04: フォーム種別分類（スタブ: 全件 inquiry）
  ↓
フォームURL重複チェック（ローカルSQLite DB）
  ↓
完了コールバック → SQLite 保存
```

4. **キーワード不足**: 「歯科」のみ → 「歯科医院」「デンタルクリニック」でヒットするケースを逃す

## カバレッジ向上策と実装状況

### 実装済み改善（v2）

#### ✅ 1. キーワード自動展開（L-02a を更新）

業種ごとにキーワードを自動展開するマップを追加。

| 業種 | v1（入力のみ） | v2（自動展開） |
|------|------------|------------|
| 歯科 | 歯科 | 歯科, 歯科医院, 歯医者, デンタルクリニック（4語） |
| 美容室 | 美容室 | 美容室, ヘアサロン, 美容院（3語） |
| 整骨院 | 整骨院 | 整骨院, 接骨院, 骨盤矯正（3語） |

**効果**: クエリ数が3〜4倍 → 取得企業数が理論上3〜4倍

#### ✅ 2. ページネーション対応（L-02b を更新）

L-02b を HTTP Request ノードから Code ノードに変換し、`nextPageToken` を使って最大3ページ取得。

```
v1: 1クエリ → 最大20件
v2: 1クエリ → 最大60件（3ページ × 20件/ページ）
```

**効果**: 各クエリの取得数が最大3倍  
**コスト増**: 1ページ → 最大3ページで $0.032 × 3 = $0.096/クエリ（最大3倍）

#### 理論的改善効果（v2 vs v1）→ 実測値で更新済み

| 指標 | v1 実測 | v2 実測（exec 34） |
|------|---------|-----------------|
| クエリ数（歯科/東京都） | 45 | **180**（4kw×45） ✓ |
| Places API 生取得数 | ~900 | **1,438** (+63%) |
| HP URL重複除去後 | ~880 | **1,322** |
| フォームURL有り | ~442 | **699**（52.9%） |
| DB新規保存（form URL重複除去後） | 442 | +262 → **累計704** |
| APIコスト/都道府県/1業種 | $1.44 | **$5.76** |
| 東京都歯科カバレッジ（DB保存ベース） | ~2.9%（442/15,000） | **~4.7%**（704/15,000） |
| 実行時間 | ~160s | **391s**（~6.5分） |

> **観察**: 4kw拡張で生取得数は+63%増加したが、DB新規保存は+59%（262件増）にとどまった。
> 理由: 同一クリニックが複数キーワードでヒットし、form URL重複チェックで弾かれた（699件中437件が既存フォームURLと重複）。
> v1実行済みエリア（東京都歯科）では増分効果が薄く、**未収集エリア・業種への適用で真価を発揮する**。

### 発見された問題と修正

| 問題 | 原因 | 修正 |
|------|------|------|
| 大都市(東京等)で `scrape-forms-bulk` 400エラー | Zod `.max(500)` に 1,300件超が引っかかる | **items上限 500→3000** に変更 |
| n8n 同時実行拒否（0〜2s で error） | 3ジョブを同時 dispatch すると n8n が一部を拒否 | **dispatch 間隔を 5s に設定**で回避 |
| completion callback 失敗（server restart 時） | コード変更による hot-reload 中に n8n が callback を送信 | （根本修正：作業中はコード変更しない運用で対処） |
| 予約SaaS URL が inquiry に分類 | BOOKING_URL_HOSTS 未登録（haisha-yoyaku.jp 等） | **BOOKING_URL_HOSTS / REDIRECT_REJECT_HOSTS に追加** |
| `/recruit_all/` 等が NON_CONTACT_SUFFIX_RE に不一致 | パターンが `/recruit` のみ | `recruit(?:ment)?(?:[-_]\w+)?` に拡張 |
