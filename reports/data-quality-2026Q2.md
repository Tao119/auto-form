## 問題 7：normalizeUrl 正規化不一致（重複32件）→ 修正済み

### 原因

`normalizeUrl()` が古い収集ラン時と新しいラン時で異なる結果を返していた。

| 原因 | 詳細 |
|------|------|
| LINE 表示用パラメータ未除去 | `?openQrModal=true`・`?oat_content=url` が NORM_TRACKING_PARAMS 未登録。旧コードは全パラメータを除去していたため、新コードで生成した normalizedFormUrl が異なる値になった |
| HTML エンティティ未デコード | `&amp;` を含む URL が URL パーサに渡されてそのまま normalizedFormUrl に残存 |
| その他 UI パラメータ | `?skin=imp`（mypl.net テンプレート）・`?page_id=`（WordPress）・`?SITE_CODE=` が未除去 |

### 影響

- 31 ペアの重複が normalizedFormUrl の不一致により dedup をすり抜けて二重挿入されていた
- 215 件の LINE URL に `openqrmodal` パラメータが正規化 URL に残存し、将来の dedup 精度が低下するリスクがあった

### 修正内容

- `NORM_TRACKING_PARAMS` を拡張（LINE 表示パラメータ・skin・page_id・SITE_CODE）
- URL パース前に `&amp; → &` デコードを追加
- パラメータマッチングを大文字小文字非区別に変更
- 起動時マイグレーション：既存レコードの normalizedFormUrl を再計算し、生じた重複を削除（古い方を保持）

**結果**: 重複 31ペア → 0ペア、削除 32件
