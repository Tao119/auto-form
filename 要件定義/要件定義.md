## 技術選定

動画内でDifyが言及されていたが、n8nを主軸とした構成を推奨。

| 観点                   | Dify         | n8n                  | 備考    |
| ---------------------- | ------------ | -------------------- | ------- |
| LLM文章生成            | ◎ 中核機能   | ○ OpenAIノード       | —       |
| スプシ読み書き         | △ 要カスタム | ◎ ネイティブノード   | n8n優位 |
| フォーム自動送信       | ✗ 非対応     | ○ 外部スクリプト連携 | n8n優位 |
| ループ処理（複数社）   | △ 扱いにくい | ◎ ネイティブ対応     | n8n優位 |
| 重複チェック/条件分岐  | △ 要コード   | ◎ Filterノード       | n8n優位 |
| エラーハンドリング     | △ 弱い       | ◎ 充実               | n8n優位 |
| 実行ログ・モニタリング | ○ 会話ログ   | ◎ 詳細な実行履歴     | n8n優位 |

> **結論**：n8nで全体ワークフローを構築し、LLM呼び出し部分はOpenAI APIを使用。Difyは本件では不採用。

### アーキテクチャ概要

`[n8nワークフロー]
    ├── Google Sheets     → 未送信リスト取得・重複チェック
    ├── HTTP + Cheerio    → 企業HPスクレイピング・フォームURL検索
    ├── OpenAI GPT-4o     → 業種別カスタム営業文章生成（500字/3000字）
    ├── Playwright        → フォーム自動入力・送信・スクショ取得
    ├── Google Drive      → スクショ自動保存・命名
    └── Slack/LINE        → エラー・完了通知`

## 機能要件定義

### 対象業種（現行マニュアルより）

- ヘッドスパ / ドライヘッドスパ
- 美容クリニック / 美容整形 / 美容皮膚科
- toCリスキリングスクール（動画編集・プログラミング・Webデザイン等）
- 中古車販売店
- YouTubeマーケティング実施企業

### 機能一覧

| #    | 機能名             | 詳細                                                                         | 優先度     |
| ---- | ------------------ | ---------------------------------------------------------------------------- | ---------- |
| F-01 | リスト読み込み     | Google Sheetsから未送信企業リストを取得。ステータス列でフィルタリング        | 必須       |
| F-02 | 重複チェック       | 会社名・URLをキーに送信済み判定。スプシの赤網掛けロジックを踏襲              | 必須       |
| F-03 | HP情報取得         | 企業URLからサービス紹介ページのテキストを自動スクレイピング                  | 必須       |
| F-04 | フォームURL検索    | HP内を走査し「お問い合わせ」ページURLを自動特定                              | 必須       |
| F-05 | 文章生成（500字）  | 業種別プロンプトでOpenAI APIを呼び出し500字版を生成                          | 必須       |
| F-06 | 文章生成（3000字） | 業種別プロンプトでOpenAI APIを呼び出し3000字版を生成                         | 必須       |
| F-07 | フォーム自動送信   | Playwrightでフォームフィールドを検出・入力・送信。文字数制限に応じて自動選択 | 必須       |
| F-08 | スクショ自動保存   | 送信完了画面をキャプチャ。会社名でファイル命名しGoogle Driveへ格納           | 必須       |
| F-09 | スプシ自動記録     | 送信日時・ステータス・エラー内容をスプシに書き戻し                           | 必須       |
| F-10 | 予約フォーム除外   | 「予約」「booking」等を含むフォームを自動除外（損害賠償リスク回避）          | 必須       |
| F-11 | エラー通知         | 送信失敗時にSlack/LINEへ即時通知                                             | 推奨       |
| F-12 | 送信レート制限     | 過剰送信防止のインターバル制御（IP制限・スパム判定対策）                     | 推奨       |
| F-13 | 業種自動判定       | HP内容からターゲット業種を自動判定しプロンプト切り替え                       | オプション |

## 非機能要件

| 項目         | 要件                                                                |
| ------------ | ------------------------------------------------------------------- |
| 送信成功率   | 初期70〜80%以上 → 改修で85%以上を目標（フォーム構造の多様性による） |
| 処理速度     | 1件あたり2〜3分（HP取得・文章生成・送信を含む）                     |
| 同時処理     | n8n並列実行により最大3〜5件同時処理可能                             |
| ログ保持     | 送信履歴・エラーログを最低90日間保持                                |
| セキュリティ | APIキー・認証情報はn8n Credentialsで管理、ソースに非含有            |
| 拡張性       | 業種別プロンプトの追加はn8nワークフロー上でノーコードで対応可能     |

## リスクと対策

| リスク                                          | 可能性 | 影響 | 対策                                              |
| ----------------------------------------------- | ------ | ---- | ------------------------------------------------- |
| フォーム構造の多様性（JS動的生成・reCAPTCHA等） | 高     | 高   | Playwright + 未対応フォームはエラーフラグで管理   |
| IP制限・送信ブロック                            | 中     | 中   | 送信インターバル制御（1〜2分/件）、User-Agent設定 |
| 予約フォームへの誤送信                          | 低     | 高   | F-10除外ロジック必須。除外キーワードリスト管理    |
| Google Sheets API制限                           | 低     | 中   | バッチ処理・待機ノードで対応                      |
| OpenAI API障害                                  | 低     | 低   | リトライ処理・通知実装                            |
